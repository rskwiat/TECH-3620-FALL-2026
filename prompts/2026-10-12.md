## Session 2 — Habit tracker API: tables, endpoints, docs, and seed data

### Context

Building the backend the Today screen (session 1) talks against: Prisma tables for habits and completion logs, the `/api/habits` routes (list, create, delete, logs, history), the unusual 404-for-unauthenticated behavior, README docs, and seeded demo data. Answers to upfront questions shaped the design: full-featured habits (name, description, color/emoji, frequency, goal, archived), `/api/habits` prefix, raw logs vs. aggregated history as separate endpoints, own-habits-only scoping with a DELETE, and a POST for logging completions. Follow-up answers: enum-style frequency + `timesPerPeriod`, history = streaks + per-day counts, and multiple completions per day allowed.

### Prompts

1. **build out the api and endpoint for the habit tracker, we need endpoints for GET habits, POST habits, GET logs, GET History and tables for saving habit data. Before writing anything ask me more questions. These routes should only work for authenticated users all other users will should get a 404**
   *(asked two rounds of questions — habit fields, logs vs. history shape, route prefix, 404 semantics, mutations, completion POST, frequency format, history payload, double-logs. Then adds `Habit` + `HabitLog` models to `api/prisma/schema.prisma` (migration `20261012222751_add_habits_and_logs`; `frequency` is a validated string because Prisma enums aren't supported on SQLite; both FKs cascade-delete) and `api/src/routes/habits.ts` mounted at `/api/habits`: `GET /` (own habits, `?includeArchived=true`), `POST /` (validated create → `201`), `DELETE /:id`, `GET /:id/logs` (oldest first, `?from=`/`?to=YYYY-MM-DD` inclusive), `POST /:id/logs` (multiple per day, optional `completedAt` backfill → `201`), `GET /:id/history` (`currentStreak`, `longestStreak`, `totalCompletions`, per-day `{ date, count, goalMet }`, `?days=1..365` default 30; UTC-day buckets, an unmet "today" doesn't break the streak). `src/middleware/auth.ts` refactored around one `checkBearerToken()` helper with two exports: the original `requireToken` (401 with a reason) and the new `requireTokenOr404` — missing, malformed, expired, and revoked tokens all get `404 {"message":"Not found"}` so habit routes appear not to exist; another user's habit id is also a 404. ### Endpoint summary after session 2

| Method | Path                    | Auth   | Description                                    |
|--------|-------------------------|--------|------------------------------------------------|
| GET    | `/api/habits`           | Bearer | Own habits; `?includeArchived=true`            |
| POST   | `/api/habits`           | Bearer | Create → `201`                                 |
| DELETE | `/api/habits/:id`       | Bearer | Delete habit + logs (cascade)                  |
| GET    | `/api/habits/:id/logs`  | Bearer | Raw logs; `?from=`/`?to=YYYY-MM-DD`            |
| POST   | `/api/habits/:id/logs`  | Bearer | Log a completion → `201`; multiple per day     |
| GET    | `/api/habits/:id/history` | Bearer | Streaks + per-day counts; `?days=1..365`     |

All of these return `404` — not `401` — for any unauthenticated request.
