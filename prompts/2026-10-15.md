## Session 1 — passwordless login with one-time 6-digit codes

### Context

Switch auth from email + password to a **one-time 6-digit code**. There is no email
provider in this POC, so the code is `console.log`-ed by the API instead of being
mailed. The work spanned the Prisma schema, the auth routes, and the Expo client.

### Prompts

1. **change the auth to use a one time six digit code … i don't have an email system setup to email the code so we can console.log it for the poc. please ask any questions on what else needs to be done to update the login**
   - asked (all answered with the recommended option):
     - scope → **Passwordless everywhere** (signup drops the password too)
     - unknown email on code request → **always generic "code sent", don't leak**
     - code storage → **SQLite table via Prisma**
     - password column → **drop password + bcrypt**
     - login UI → **one screen, reveal the code field after requesting**
     - code delivery for testing → **console only** (not in the response body)
   *(Implemented as below.)*

### Decisions / defaults

- Code: **6 digits**, zero-padded, generated with `crypto.randomInt` (CSPRNG).
- Stored **SHA-256 hashed**; compared with `crypto.timingSafeEqual`.
- **10-minute** expiry, **single-use**, **5-attempt** limit, one active code per user
  (a new request replaces the old one). No rate limiting yet — noted as a TODO.

### Endpoints

| Method | Path | Body | Result |
| ------ | ---- | ---- | ------ |
| POST | `/signup` | `{ name, email, age?, home_address? }` | `201` + JWT + user (auto-login) |
| POST | `/login` | `{ email }` | generic `200`; real accounts get a code logged to the console |
| POST | `/login/verify` | `{ email, code }` | `200` + JWT + user, or `401 Invalid or expired code` |
